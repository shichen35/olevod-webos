# OleVod Streaming API Integration Notes

This document is the **backend API integration reference** for the OleVod
LG webOS TV client. It describes how the app cooperates with the OleVod
backend across the full chain — "content list -> episode detail -> fetch
playback URL -> pull the stream". It's meant for client development and
integration testing. Findings marked "**verified**" reflect the actual API
responses observed on 2026-07-02; defer to the live API if it changes.

> Note: this document records the backend's **available endpoints**,
> including the search endpoint. The current app version has no search UI —
> content discovery goes through home shelves and category filters
> (`categoryList`); the search endpoint is kept here for reference as a
> backend capability.

---

## 1. TL;DR

- **API gateway**: `https://api.olelive.com`, plain JSON API.
- **Request signing**: every GET request carries a `_vv=<signature>` query
  parameter, generated by the client from the current Unix timestamp in
  seconds (see §4.2). The gateway returns `401` if it's missing.
- **Playback URL**: calling `/v1/pub/vod/detail/{id}/true` returns episode
  detail, and the `urls[]` array in the response **inlines** the HLS
  playback URL for every episode directly — no second request needed.
- **Media format**: standard HLS. CDN is `*.olemovienews.com`, following
  master.m3u8 -> media playlist -> `.ts` segments. SD/HD tiers are
  unencrypted HLS, and segments support HTTP `Range` (206), so they can be
  handed directly to `hls.js` / `<video>`.
- **Integration takeaways**: the pipeline is simple — the signature is
  computed locally on the client, and the playback URL is inlined by the
  detail endpoint. The client mainly needs to handle cross-origin (CORS),
  Referer, and the remote-control UI.

---

## 2. Verification Method

During integration, `curl` and scripts were used to call `api.olelive.com`,
walking the layers "list -> get a real `vodId` -> detail -> master.m3u8 ->
`.ts` segment" to confirm the response structure and playback viability at
each step, as the basis for the client implementation.

## 3. Streaming Pipeline Overview

OleVod's streaming pipeline is short: the client generates a
timestamp-based signature -> calls the detail endpoint -> gets the HLS URL
directly.

```
List / Detail   GET api.olelive.com  + _vv(timestamp) signature
        │
        ▼
detail.urls[] inlines m3u8
        │
        ▼
HLS master.m3u8  (*.olemovienews.com)
        │
        ▼
media playlist → .ts segments
```

Client-side notes:

- Calling the API directly from the browser/webview involves **CORS** and
  **Referer** concerns; in the packaged environment, a **local HTTP proxy**
  layer handles request headers uniformly.
- On webOS, `<video>` / the player can only load a URL, so JSON exchange for
  the API goes through the Luna service while media goes through the local
  proxy — this is the "Luna service + local proxy" dual channel.

## 4. API Layer

### 4.1 Gateway and Request Headers

- Base: `https://api.olelive.com`.
- Gateway auth relies solely on the `_vv` signature and does **not** check
  Referer / Origin; a normal browser UA is sufficient. For the CDN (media
  segments), it's recommended to consistently send
  `Referer: https://www.olevod.com/` and **not** send `Origin`.

### 4.2 `_vv` Request Signature

Every GET request appends `?_vv=<sig>`; the signature input is the current
Unix timestamp in seconds, generated locally by the client:

```python
import hashlib, time

def _vv(ts: int) -> str:
    t = str(ts)
    cols = ["", "", "", ""]
    for ch in t:                      # for each digit character
        b = bin(ord(ch))[2:]          # ASCII -> binary string (e.g. '1' -> '110001')
        cols[0] += b[2:3]             # take bit 2
        cols[1] += b[3:4]             # take bit 3
        cols[2] += b[4:5]             # take bit 4
        cols[3] += b[5:]             # take bit 5 onward
    pieces = []
    for s in cols:                    # each column's binary -> 3-char zero-padded hex
        hx = format(int(s, 2), "x") if s else ""
        hx = ("000" if len(hx) == 0 else
              "00" + hx if len(hx) == 1 else
              "0"  + hx if len(hx) == 2 else hx)
        pieces.append(hx)
    n = hashlib.md5(t.encode()).hexdigest()   # md5 of the timestamp
    return (n[0:3]  + pieces[0] +
            n[6:11] + pieces[1] +
            n[14:19]+ pieces[2] +
            n[22:27]+ pieces[3] +
            n[30:])

# Usage: url = f"{API}{path}?_vv={_vv(int(time.time()))}"
```

Key points:

- The signature interleaves several segments of `md5(timestamp)` with 4
  short hex chunks derived by "transposing" bits out of each digit of the
  timestamp; its purpose is to check request-timestamp freshness.
- Computed entirely locally by the client — no need to fetch any key from
  the server first.
- **Verified**: no `_vv` -> `HTTP 401`; correct `_vv` -> `HTTP 200`. The
  signature scheme is currently working.
- Since it depends on device time, an inaccurate clock on webOS could cause
  the signature to expire; consider unifying the timestamp source.

### 4.3 Endpoint List

| Function | Method and Path | Notes |
|------|-----------|------|
| Navigation tree | `GET /v1/pub/index/navs` | Top-level categories + sub-types (gzip, plain JSON) |
| Filter dimensions | `GET /v1/pub/vod/list/type` | children / area / year for each top-level category |
| Top-level category content | `GET /v1/pub/index/vod/data/{typeId}` | Returns `{list, rank}`, used for the category's first screen |
| Filtered pagination | `GET /v1/pub/vod/list/{10-segment params}` | Server-side filter+sort+pagination, returns `{list,total,page,pageSize}` (see below) |
| Search | `GET /v1/pub/index/search/{keyword}/0/0/0/1` | keyword needs URL-encoding |
| Hot search terms | `GET /v1/pub/index/search/hot/keywords?limit=6` | |
| Detail + episodes | `GET /v1/pub/vod/detail/{vodId}/true` | Metadata + `urls[]` playback URLs |

> Some list-type endpoints return gzip bodies; a few endpoints' `data` field
> is an AES-CBC ciphertext string (key = `md5("YYYY-MM-DD")[8:24]`, IV=key,
> PKCS7, base64) — decrypting it on the client yields JSON. Signing and
> decryption utilities are in
> [app/src/api/sign.js](../app/src/api/sign.js).

**Filtered pagination endpoint** `GET /v1/pub/vod/list/{...}` (sourced from
the web frontend's `pubVodList(...)`, verified 2026-07-02) — the path has 10
segments:

```
/v1/pub/vod/list/{flag}/{vip}/{letter}/{area}/{category}/{genre}/{year}/{order}/{page}/{size}
```

| Segment | Meaning | Values |
|----|------|------|
| flag | fixed flag | always `true` |
| vip | membership-tier filter | `3`=all · `1`=members only · `2`=free only. Note: 4K/UHD entries have `vip:false`, and this param does **not** filter 4K/UHD content; the client always sends `3` |
| letter | first letter A–Z | `0`=unrestricted (unused by this client) |
| area | region | `0`=all, otherwise a region name (e.g. `大陆` (Mainland China) / `美国` (USA)…, needs URL-encoding) |
| category | top-level typeId | Movies `1` · TV Series `2` · Variety `3` |
| genre | sub-type typeId | `0`=all, otherwise e.g. `101` |
| year | year | `0`=all, otherwise `"YYYY"` |
| order | sort | `update` (by `vodTime`, newest) · `hot` (by `hits`, most popular) · `score` (by `score`, rating) |
| page | page number | starting from `1` |
| size | page size | e.g. `24` |

Returns `data = { list, total, page, pageSize }`; `list` entries have the
same structure as search results, plus `hits` (popularity) and `vodTime`
(update time in seconds). **Important**: the `order` segment must be
non-empty, otherwise the server only returns `total` and `list` is `null`.
The client wraps this in `categoryList()` in
[app/src/api/olevod.js](../app/src/api/olevod.js).

### 4.4 Key Response Structures

**Search**: `data.data` is an array bucketed by content type; entries live
in the `list` field of the `vod` bucket:

```jsonc
{ "code": 0, "msg": "ok",
  "data": { "total": 4,
    "data": [ { "type": "vod", "list": [ {
        "id": 55678, "name": "庆余年 第二季",
        "typeId": 202, "typeId1": 2,
        "pic": "upload/vod/.../xxx.jpg",       // relative path, prefix with the image CDN
        "actor": "...", "director": "孙皓",
        "score": 7.1, "remarks": "完结", "vip": false, "year": 2024
    } ] },
    { "type": "tv", "list": [] } ]
  } }
```

(Sample data above: `"name"`, `"director"`, and `"remarks"` are genuine
Chinese content values from the live API — e.g. `remarks: "完结"` means
"completed"/finished airing — left as-is since they are actual API data,
not UI text to translate.)

**Detail**: `data.urls[]` — each episode's playback URL is directly here:

```jsonc
{ "code": 0, "msg": "ok",
  "data": {
    "id": 55678, "name": "庆余年 第二季", "total": 36,
    "typeIdName": "...", "area": "...", "year": 2024, "content": "...",
    "urls": [
      { "index": 1, "title": "第01集",
        "url": "https://europe.olemovienews.com/ts3/.../master.m3u8",
        "seek_start": 0, "seek_end": 0, "vip": false }
      // ... 36 entries total
    ]
  } }
```

(`"title": "第01集"` means "Episode 01" — a genuine data value, left
as-is.) Entries with `vip: true` are members-only content. The detail
endpoint's synopsis field is **`content`** (not `blurb`).

## 5. Playback Pipeline

### 5.1 Steps to Get a Stream

```
categoryList(...) ──►  vodId (e.g. 55678)
detail(vodId)     ──►  data.urls[i].url = master.m3u8
GET master.m3u8   ──►  #EXT-X-STREAM-INF ... index-v1-a1.m3u8
GET index-*.m3u8  ──►  seg-1-v1-a1.ts, seg-2-v1-a1.ts ...
```

master.m3u8 is standard HLS; the media playlist is a `#EXTINF` +
`seg-*.ts` list.

### 5.2 Media Layer Details

| Item | Finding |
|------|------|
| Container/codec | HLS / TS segments, H.264 (`avc1.640028`) + AAC (`mp4a.40.2`) |
| Encryption | SD/HD tiers are unencrypted HLS (no `#EXT-X-KEY`), playable directly |
| Quality | master may contain multiple tiers; UHD (4K/2K) is verified playable without login |
| Referer | not enforced by the CDN, but recommended to always send it; **do not** send `Origin` (sensitive cases return 403) |
| Range | `.ts` segments support `Range` (`206 Content-Range`) |
| CDN domain | `*.olemovienews.com` (nodes split by region); images go through `static.olelive.com` |

> The CDN splits nodes by region — write the proxy's host allowlist as a
> suffix match `*.olemovienews.com` to cover all regional domains.

## 6. Architecture for the webOS Client

```
┌───────────────────────── LG webOS TV ─────────────────────────┐
│  React App (Chromium)                                          │
│    │  JSON: list/detail/category      Media: m3u8 + .ts        │
│    ▼        ▼                              ▼                   │
│  Luna Service (Node)              Local HTTP Proxy(:PORT)      │
│    - calls api.olelive.com          - host allowlist            │
│    - handles CORS / headers         - injects Referer           │
│    - returns decompressed JSON      - passes through Range/CORS │
└──────────┼──────────────────────────────┼─────────────────────┘
           │ HTTPS                          │ HTTPS
           ▼                                ▼
     api.olelive.com                *.olemovienews.com
```

- **Signature location**: `_vv` is computed on the frontend (both channels
  share the same implementation).
- **Player**: on webOS 24 (Chromium 108), `hls.js` is sufficient since the
  stream is standard HLS. In the browser dev environment, both the OleVod
  API and the CDN return `Access-Control-Allow-Origin: *`, so direct
  connection works without a proxy.
- **Proxy allowlist**: `api.olelive.com`, `*.olemovienews.com`,
  `static.olelive.com`.
